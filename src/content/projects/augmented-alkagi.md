## 어떤 프로젝트인가

바둑판 위에서 알을 당겼다 놓아 상대 알을 장외로 밀어내는 알까기에, 매치 도중 뽑은 **증강 카드로 내 알의 규칙 자체를 바꾸는 증강 드래프트**를 결합한 1\~4인 개인전입니다. 알이 머스킷을 쏘는 전열보병, 랜스를 든 나이트, 비숍, 얼음 알, UAV 편대를 거느린 모선으로 변신하거나, 두 번 맞힌 상대 알을 내 편으로 포섭하는 등 증강이 한 판의 흐름을 뒤집습니다.

같은 보드·증강 규칙 위에서 **턴 정책만 갈아 끼워** 세 가지 모드를 제공하는 것이 구조의 핵심입니다.

| 모드 | 턴 정책 |
| --- | --- |
| 일반전 | 싱글플레이와 같은 순차 턴 |
| 동시확정전 | 전원이 비공개로 조준을 확정하고, 서버가 같은 물리 프레임에 일괄 발사 |
| 난장판전 | 알 5개로 동시에 쏘고 받는 실시간 |

## 내가 맡은 것

1인 개발입니다. 게임 모듈과 `PreLoadingScreen` 로딩 모듈 2개로 구성하고, 게임플레이·네트워크·UI를 C++ 중심으로 구현했습니다.

## 핵심 기능

| 기능 | 요약 |
| --- | --- |
| Actor 기반 GAS | 증강이 플레이어가 아니라 알 하나하나에 귀속돼야 해서, `ACharacter` 대신 일반 `AActor`인 바둑알이 ASC와 AttributeSet을 직접 소유 |
| 증강 39종 데이터 파이프라인과 공정 드래프트 | 69종 enum 중 플레이 가능한 39종만 Database 테이블로 관리. 같은 라운드의 전 좌석이 같은 티어 구성을 받되 카드는 겹치지 않게 |
| 변신 증강 10종 | 서버 권한 컴포넌트와 "직접 발사만 인정" 규칙으로 서로 충돌 없이 조합 |
| 드래그 플릭 물리 | 드래그 거리를 충격량에 선형 매핑하고, 물리 템포 상수로 이동 거리는 유지한 채 한 턴을 1.5배 빠르게 |
| PhysicsResolutionId 기반 임시 효과 정산 | 임시 증강의 지속시간을 초가 아니라 "물리 정산이 끝나는 시점"에 묶어 렉이나 긴 충돌 연쇄에도 끊기지 않게 |
| 턴 정책 3종 | 보드·증강 규칙은 하나로 두고 턴 정책 enum만 바꿔 순차·동시확정·실시간 모드 구현 |
| Steam 리슨 서버와 호스트 마이그레이션 | 세션 생성·검색·빠른 매칭·비밀번호·재접속을 GameInstance 서브시스템 한 곳에 모으고, 전원 ACK된 체크포인트로 후계 호스트가 매치를 이어받음 |
| 2D 물리 예측 기반 로컬 AI | 실제 월드를 건드리지 않는 경량 2D 예측으로 방향 × 세기 후보를 평가 |
| CommonUI 3레이어 스택 | 위젯이 입력 모드와 포커스를 스스로 선언하고 Activation Stack이 복원을 대신 |
| 5개 언어 현지화와 로딩 스크린 모듈 | `LOCTEXT` → `.po` → `.locres` 파이프라인, 엔진 초기화 전부터 현지화된 팁 표시 |

## 트러블슈팅

| 문제 | 원인과 해결 |
| --- | --- |
| 패드 지원을 추가했더니 마우스 드래그가 두 번 클릭해야 동작 | CommonInput의 "현재 입력 타입"을 조준 소유권처럼 쓴 회귀. 조준 출처를 None/Mouse/Gamepad로 따로 저장하고 시작한 장치만 종료하도록 분리 |
| 육중함 증강을 골라도 달라진 게 보이지 않음 | 질량과 발사 배율만 바뀌어 외형이 같았음. 물리 배율과 별개로 크기 배율을 따로 둠 |
| 패키징 Cook 실패와 메인 메뉴 검은 화면 | 하나로 보였던 실패가 에셋 경로 불일치, 플러그인 스캔 설정, 생성자 물리 초기화 시점의 세 가지 원인 |
| 게임은 끝났는데 결과 화면이 안 나옴 | 작업한 WBP와 실제 실행되는 WBP가 달랐고, `BindWidgetOptional`이 불일치를 컴파일 타임에 숨김 |
| 한 PC에서 멀티 테스트하면 이전 참가자가 사라짐 | 동일 EOS ID 중복 접속 정리 로직 때문. Dev Auth Tool로 창마다 다른 계정을 붙임 |
| 로비 채팅을 갱신하면 PIE 종료 시 에디터 크래시 | 위젯 재생성 때문에 Undo 버퍼가 죽은 위젯을 잡고 있었음. 위젯을 고정하고 내용만 갱신 |
