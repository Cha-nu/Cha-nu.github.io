## 들어가며

[지난 기록](/posts/vkb2xbox-2026-11-11-firmware-calibration/)에서 VKB Gladiator EVO R의 초기 설정을 마쳤습니다. 이번에는 이 스틱으로 에이스 컴뱃 8을 하기 위해, 스틱 입력을 Xbox 패드 입력으로 바꾸는 프로그램 vkb2xbox를 만들었습니다.

코드는 [GitHub 저장소](https://github.com/Cha-nu/vkb2xbox)에 있습니다.

---

## 요구사항

에이스 컴뱃 8은 이 스틱을 지원하지 않지만 Xbox 360 컨트롤러는 지원합니다. 그래서 스틱 입력을 가상 Xbox 360 컨트롤러에 매핑해서 쓰기로 했습니다.

- 스틱의 축, 버튼, 햇을 Xbox 360 패드의 스틱, 트리거, 버튼에 자유롭게 연결합니다.
- 게임 창에 포커스가 있어도 계속 동작합니다.
- 매핑은 번호를 입력하는 대신 스틱을 직접 움직여서 지정합니다.
- 스틱 하나뿐 아니라 별도 스로틀, 러더 페달 같은 장치를 함께 쓸 수 있습니다.

---

## 한 일

1. 변환 코어(`vkb2xbox.py`)를 만들었습니다. 매핑 마법사(`setup`), 변환 실행(`run`), 원시 입력 확인(`monitor`) 세 명령이 있습니다.
2. GUI(`vkb2xbox_gui.py`)를 만들었습니다. 표에서 Xbox 출력을 고르고 스틱을 움직이면 그 입력이 지정됩니다. 오른쪽 패드 그림은 가상 패드의 실제 출력을 보여 줍니다.
3. 입력 하나로 버튼 두 개를 동시에 누르는 조합 출력(`LB+RB`, `LT+RT`, `LS+RS`)을 넣었습니다.
4. 여러 장치를 동시에 쓸 수 있게 바꿨습니다. 연결된 조이스틱을 모두 열고, 매핑마다 어느 장치의 입력인지 저장합니다.

---

## 아이디어와 설계

흐름은 세 단계입니다. pygame(SDL)으로 조이스틱을 읽고, 매핑 표에 따라 Xbox 패드 상태를 계산하고, [vgamepad](https://github.com/yannbouteiller/vgamepad)로 만든 가상 Xbox 360 패드에 보냅니다. 가상 패드는 ViGEmBus 드라이버가 Windows에 연결해 줍니다. 명령줄 실행에서는 4ms를 쉬고 다시 계산하며, 상태가 바뀌었을 때만 패드에 보냅니다.

비행 조작은 아래처럼 연결했습니다. 제가 쓰는 매핑이고, GUI에서 바꿀 수 있습니다.

| 스틱 입력 | Xbox 출력 | 처리 |
| --- | --- | --- |
| 롤, 피치 축 | 왼쪽 스틱 X, Y | 데드존 2% |
| 스로틀 축 | RT(가속), LT(감속) | 가운데가 중립, 위아래 절반씩, 데드존 15% |
| 트위스트(요) 축 | RB, LB | 30% 넘게 비틀면 버튼 눌림 |
| 햇 | 오른쪽 스틱(카메라) | 방향마다 끝까지 기울임 |
| 버튼 하나 | LB+RB, LT+RT 동시 | 조합 출력 |

모든 입력은 0.0\~1.0 값 하나로 바꿔서 다룹니다. 버튼과 햇은 0 아니면 1이고, 축은 데드존을 뺀 나머지 구간을 0\~1로 늘립니다. 이렇게 하면 축을 버튼에, 버튼을 스틱 방향에 연결하는 경우를 따로 만들지 않아도 됩니다.

```python
# 축 하나를 0.0~1.0으로. sign은 방향, min은 데드존
v = j.get_axis(s["index"]) * s["sign"]
lo = s.get("min", 0.0)
hi = s.get("max", 1.0)
if v <= lo:
    return 0.0
return min(1.0, (v - lo) / (hi - lo))
```

축 하나를 방향별로 나눠 `LX+`와 `LX-`처럼 출력 두 개에 따로 연결하고, 왼쪽 스틱 X 값은 둘의 차로 계산합니다. 스로틀 축을 RT와 LT로 나누는 것도 같은 방식입니다.

여러 장치 지원에서는 매핑 항목에 `device`(조이스틱 이름)를 추가했습니다. `device`가 없는 예전 매핑은 설정 파일의 기본 장치 이름으로 찾기 때문에 기존 설정이 그대로 동작합니다.

실제 스로틀과 러더 페달로는 아직 확인하지 못했습니다.

## 막힌 점과 해결

- 문제: 실행 중에 장치를 꽂거나 뽑아도 프로그램이 알아채지 못했습니다.
  - 원인: 이 프로그램은 창이 없어서 SDL 비디오 드라이버를 `dummy`로 씁니다. 이 상태에서는 장치 변화 알림이 처리되지 않는 것으로 보입니다. 가상 패드를 꽂고 8초를 기다려도 `JOYDEVICEADDED` 이벤트가 오지 않았고 장치 수는 0에서 변하지 않았습니다.
  - 해결: 환경 변수 [`SDL_JOYSTICK_THREAD`](https://wiki.libsdl.org/SDL2/SDL_HINT_JOYSTICK_THREAD)를 `1`로 설정해 장치 감지를 별도 스레드에서 하게 했습니다. 같은 조건에서 꽂은 지 약 0.9초 뒤에 이벤트가 왔고, 뽑을 때도 `JOYDEVICEREMOVED`가 왔습니다. (pygame 2.6.1, SDL 2.28.4, Windows 11. 확인 스크립트는 `research/vkb2xbox/hotplug_probe.py`)
- 문제: 모든 조이스틱을 열자 프로그램이 만든 가상 패드까지 입력 장치로 잡혔습니다.
  - 원인: 가상 패드도 Windows에서는 조이스틱 하나로 보입니다. 이것을 입력으로 쓰면 출력이 다시 입력으로 들어갑니다.
  - 해결: 이름에 `Xbox`, `XInput`이 들어간 장치는 입력 목록에서 뺐습니다. 실제 Xbox 패드도 입력으로 쓸 수 없게 되지만, 이 프로그램의 용도에서는 문제가 되지 않습니다.
- 문제: 갓 만든 가상 패드가 스틱이 약간 쏠린 값을 보고했습니다.
  - 원인: 처음부터 중립(전부 0)을 보내면 변화가 없는 보고로 처리되어 무시됩니다.
  - 해결: 0이 아닌 값을 한 번 보낸 뒤 중립을 보냅니다.
- 문제: 다른 패드가 꽂혀 있으면 가상 패드가 XInput 2번이 됩니다.
  - 해결: GUI가 가상 패드의 슬롯 번호를 찾아 1번이 아니면 경고를 표시합니다.
