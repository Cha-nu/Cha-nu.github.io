## 들어가며

ProjectH는 횡스크롤 런앤건 게임입니다. 같은 게임 규칙을 브라우저 Canvas 버전(`web/game.js`)과 Godot 4.7.1 버전(`scripts/honey_game.gd`) 두 곳에 맞춰 구현하고 있습니다. 요구사항과 판단은 제가 정하고, 코드는 Claude Code와 함께 작성했습니다.

이 글은 점프 입력을 너그럽게 받아 주는 두 가지 보정, 코요테 타임(Coyote Time)과 점프 선입력(Jump Buffer)을 정리합니다. 같은 코드 줄에서 아랫점프가 동작하지 않던 문제도 함께 다룹니다.

---
## 요구사항

2026년 10월 23일, 발판을 벗어나 발이 뜬 뒤에도 잠깐은 점프가 되는 보정을 넣어 달라고 요청했습니다.

코드를 확인해 보니 코요테 타임은 이미 0.1초로 들어가 있었습니다. 0.1초는 60fps에서 6프레임이라 짧을 수 있다는 검토 결과를 듣고, 0.15초로 늘리기로 했습니다. 같은 날 아래 + 점프로 발판을 내려가는 아랫점프도 되게 해 달라고 요청했습니다.

- 발판 끝을 지나친 직후에 누른 점프가 나가야 합니다.
- 아래 + 점프는 얇은 발판 위에서만 발판을 통과해 내려가야 합니다.
- 웹과 Godot 두 버전이 같은 값, 같은 순서로 동작해야 합니다.

---
## 코요테 타임: 땅을 떠난 뒤에도 잠깐은 땅으로 친다

발판 끝에서 점프를 누르는 순간, 캐릭터는 이미 한두 프레임 전에 발판을 벗어났을 수 있습니다. 판정만 보면 공중이라 점프가 나가지 않고, 플레이어는 "눌렀는데 떨어졌다"고 느낍니다.

코요테 타임은 땅을 떠난 뒤 짧은 시간 동안은 아직 땅에 있는 것으로 쳐 주는 보정입니다. 구현은 타이머 하나입니다. 땅에 닿아 있는 동안은 타이머를 0.15초로 계속 채우고, 공중에 뜨면 그때부터 줄입니다. 점프 조건은 `grounded` 대신 `coyote > 0`을 봅니다.

```js
// web/game.js, updatePlayer() 중 점프 부분
this.jumpBuffer -= dt;
this.coyote = this.grounded ? .15 : this.coyote - dt;   // 땅에 있으면 0.15초로 채우고, 떠 있으면 줄인다
if (this.jumpBuffer > 0 && this.coyote > 0) {
  this.vy = -810; this.grounded = false;
  this.jumpBuffer = 0; this.coyote = 0;                  // 한 번 쓰면 둘 다 비운다 (공중에서 두 번 뛰지 않게)
}
```

점프가 나가면 `coyote`를 0으로 비웁니다. 비우지 않으면 점프 직후 남은 시간 동안 한 번 더 뛸 수 있어서 이단 점프가 됩니다.

![0.10초와 0.15초 설정에서 발판을 벗어난 뒤 1~12번째 프레임에 점프를 눌렀을 때의 결과. 0.10초는 6프레임까지, 0.15초는 9프레임까지 점프가 나갑니다.](/images/project-h-tech-coyote-time/01_coyote_window.png)

*`web/game.js`의 점프 판정을 옮긴 시뮬레이션 결과입니다. 아래 줄은 그 프레임까지 이미 떨어진 높이입니다.*

0.10초에서는 벗어난 뒤 6프레임째(100ms)까지, 0.15초에서는 9프레임째(150ms)까지 점프가 나갑니다. 9프레임째면 캐릭터는 이미 약 25px 떨어진 상태입니다. 같은 시뮬레이션에서 점프 높이는 약 190px이라서, 잃는 높이는 그 13% 정도입니다.

같은 값으로 실제 `web/game.js`의 `Game`을 돌려서도 확인했습니다. 시뮬레이션과 똑같이 9프레임째까지 점프가 나갔습니다.

![발판 끝에서 8프레임 늦게 점프를 눌렀을 때의 궤적. 0.10초 설정에서는 입력이 무시되어 바닥으로 떨어지고, 0.15초 설정에서는 그 자리에서 점프가 나갑니다.](/images/project-h-tech-coyote-time/02_trajectories.png)

## 점프 선입력: 착지 직전에 누른 점프를 기억한다

코요테 타임이 늦게 누른 입력을 살린다면, 점프 선입력은 일찍 누른 입력을 살립니다. 착지하기 직전에 점프를 누르면 그 순간은 공중이라 점프가 나가지 않습니다. 플레이어 입장에서는 착지하자마자 뛰려고 누른 것입니다.

그래서 점프 버튼을 누른 순간을 0.12초 동안 `jumpBuffer`에 기억합니다. 그 사이에 착지해서 `coyote`가 다시 채워지면, 그 프레임에 점프가 나갑니다. 두 타이머가 같은 조건문 하나(`jumpBuffer > 0 && coyote > 0`)로 묶여 있어서, 늦은 입력과 이른 입력을 같은 코드가 처리합니다.

| 보정 | 살리는 입력 | 값 | 기준 |
| --- | --- | --- | --- |
| 코요테 타임 | 발판을 벗어난 뒤 늦게 누른 점프 | 0.15초 (60fps에서 9프레임) | 마지막으로 땅에 있던 시점 |
| 점프 선입력 | 착지 전에 미리 누른 점프 | 0.12초 | 점프 버튼을 누른 시점 |

## 아랫점프가 안 되던 이유

아랫점프는 얇은 발판 위에서 아래 + 점프를 누르면 발판을 통과해 내려가는 기능입니다. 코드는 있었지만 실제로는 동작하지 않았습니다. 원인은 두 가지였습니다.

1. **점프 판정이 먼저 실행됐습니다.** 아래 + 점프를 눌러도 점프 판정이 먼저 그 입력을 가져가서, 일반 점프로 처리됐습니다.
2. **발판 무시가 한 프레임만 적용됐습니다.** 첫 번째 문제를 넘겨도, 발판을 무시하는 처리가 누른 그 프레임에만 적용됐습니다. 그래서 다음 프레임에 같은 발판에 다시 착지했습니다.

고친 방법은 다음과 같습니다.

```js
// 점프 버튼을 누른 프레임: 아랫점프인지 먼저 가린다
if (input.jumpPressed) {
  if (this.grounded && input.down && this.standOn && this.standOn !== 'belt' && this.standOn !== 'boat')
    this.dropTimer = .2;      // ✅ 0.2초 동안 발판 착지를 막는다 (점프 선입력은 남기지 않는다)
  else
    this.jumpBuffer = .12;    // 그 밖에는 일반 점프로 선입력
}
// 발판 착지 판정: 위에서 내려오는 중이고, dropTimer가 남아 있으면 얇은 발판은 건너뛴다
if (this.x > p.x - 12 && this.x < p.x + p.w + 12 && oldY <= p.y + 3 && this.y >= p.y && this.vy >= 0
    && !(this.dropTimer > 0 && p.type !== 'belt' && p.type !== 'boat')) {
  this.y = p.y; this.vy = 0; this.grounded = true; this.standOn = p.type;
}
```

- 아래 + 점프는 점프 선입력을 남기지 않고 `dropTimer`만 0.2초로 켭니다. 그래서 점프 판정이 이 입력을 가져가지 않습니다.
- `dropTimer`가 남은 0.2초 동안은 같은 발판에 다시 착지하지 않습니다.
- 지금 어떤 발판 위에 서 있는지 `standOn`에 기억합니다. 바닥(지면)에 서 있으면 `standOn`이 비어 있어서, 아래 + 점프가 그냥 일반 점프로 나갑니다.
- 컨베이어 벨트(`belt`)와 배(`boat`)는 통과할 수 없게 했습니다. 배 아래는 물이라서, 내려가면 바로 죽기 때문입니다.

## 두 버전에 같이 반영하기

이 게임은 웹과 Godot 두 버전의 규칙이 같아야 합니다. 그래서 값과 처리 순서를 그대로 옮기고, 두 쪽에 같은 이름의 테스트를 넣었습니다.

```gdscript
# scripts/honey_game.gd, 같은 순서와 같은 값
dropTimer -= dt; jumpBuffer -= dt; coyote = .15 if grounded else coyote - dt
if jumpBuffer > 0 and coyote > 0:
	vy = -810; grounded = false; jumpBuffer = 0; coyote = 0
```

테스트 이름은 "down + jump drops through a platform; coyote jump works just after walking off"입니다. 발판을 벗어나 7프레임(약 0.117초)이 지난 뒤 점프를 누르는 상황을 넣었습니다. 0.1초였다면 실패하고, 0.15초에서는 통과합니다. 같은 테스트에서 아래 + 점프로 발판을 통과해 바닥까지 내려가는지도 확인합니다. 당시 테스트는 Godot 40개, 웹 42개가 모두 통과했습니다.

| 결정 | 선택 | 이유 |
| --- | --- | --- |
| 코요테 타임 | 0.1초 → 0.15초 | 0.1초는 6프레임뿐이고, 9프레임째에 잃는 높이는 약 25px(점프 높이의 13%)입니다 |
| 점프 선입력 | 0.12초 유지 | 늦은 입력과 이른 입력을 같은 조건문 하나로 처리합니다 |
| 아랫점프 | 입력 분기 + 0.2초 착지 무시 | 점프 판정보다 먼저 가려야 하고, 한 프레임 무시로는 같은 발판에 다시 섭니다 |
| 통과 불가 발판 | 벨트, 배 | 배 아래는 물이라 내려가면 바로 죽습니다 |

## 마치며

코요테 타임과 점프 선입력은 둘 다 플레이어가 누른 입력이 조금 이르거나 늦어도 의도대로 받아 주는 장치입니다. 구현은 타이머 두 개와 조건문 하나로 끝나지만, 값이 6프레임에서 9프레임으로 바뀌는 차이가 손에 느껴지는 차이였습니다.

아랫점프는 같은 입력(점프 버튼)을 여러 기능이 나눠 쓸 때, 어느 쪽이 먼저 입력을 가져가는지가 중요하다는 것을 보여 준 문제였습니다. 다음 글에서는 ProjectH의 다른 큰 주제를 정리하려 합니다.
