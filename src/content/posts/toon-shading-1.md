## 들어가며

애니메이션풍 게임의 캐릭터는 실사 게임과 다르게 명암이 두세 단계로 뚝 끊깁니다. 처음에는 유튜브 강의([Unreal Engine 5 - Toon Shader Tutorial](https://youtu.be/GAkxpwy9xtg))를 보고 Half-Lambert에 SmoothStep 두 단계를 걸어 3톤을 만들고, 림라이트를 더한 셰이더를 만들었습니다. 그런데 캐릭터에 다른 물체의 그림자가 지지 않았고, 눈은 생기 없이 어두웠고, 전체적으로 원작보다 밝게 떴습니다.

이 글에서는 그 원인을 따라가며 툰 셰이더를 이루는 기법을 하나씩 정리합니다. 명암 단계, 그림자 받기, 림라이트, 얼굴 그림자, 눈, 외곽선 순서입니다. 노드로 어떻게 만들었는지는 2편에서 다룹니다.

## 명암이 부드러우면 셀 애니메이션처럼 보이지 않습니다

빛을 받는 정도는 보통 램버트(Lambert) 모델로 계산합니다. 표면의 노멀 N과 빛 방향 L의 내적이 밝기가 됩니다. 정면으로 받으면 1, 옆에서 받으면 0, 뒤쪽은 0으로 잘립니다.

```text
// ❌ 실사용 명암: 밝기가 연속으로 변합니다
brightness = max(dot(N, L), 0)
color      = baseColor * brightness
```

문제는 이 값이 연속적이라는 점입니다. 그림 왼쪽 구처럼 밝은 곳에서 어두운 곳까지 그라데이션이 생기고, 빛 반대편 절반은 완전히 검게 됩니다. 셀 애니메이션은 이런 그라데이션 대신 면을 몇 개의 색으로 나눠 칠합니다.

![Lambert, Half-Lambert, 툰 3단계로 칠한 구 비교](/images/toon-shading-1/01_spheres.png)

왼쪽은 그라데이션이 길고 절반이 검습니다. 오른쪽은 같은 빛인데 밝은 면, 좁은 중간톤, 그림자 세 덩어리로 나뉩니다.

## Half-Lambert와 SmoothStep으로 면을 나눕니다

먼저 하프 램버트(Half-Lambert)로 -1에서 1인 N·L을 0에서 1 범위로 옮깁니다. 뒤쪽도 완전히 검지 않고 값을 갖게 되어, 그림자 쪽 색을 따로 정할 여지가 생깁니다.

$$
L_{half} = N \cdot L \times 0.5 + 0.5
$$

그다음 스무스스텝(SmoothStep)으로 이 값을 자릅니다. SmoothStep(a, b, x)는 x가 a보다 작으면 0, b보다 크면 1이고, 그 사이만 부드럽게 이어집니다. a와 b 사이를 좁게 잡으면 계단에 가까워집니다. 두 번 자르면 경계가 두 개 생겨 면이 셋으로 나뉩니다.

```text
// ✅ 3단계 셀 셰이딩
L            = dot(N, Light) * 0.5 + 0.5
drawShadow   = smoothstep(0.35 - 0.05, 0.35 + 0.05, L)   // 그림자 경계
drawOuter    = smoothstep(0.40 - 0.01, 0.40 + 0.01, L)   // 중간톤 경계
tone         = lerp(shadowColor, outerShadowColor, drawShadow)
tone         = lerp(tone, 1.0, drawOuter)
color        = baseColor * tone
```

![N·L에 따른 Lambert, Half-Lambert, 툰 곡선](/images/toon-shading-1/02_curves.png)

주황색 툰 곡선은 L=0.30\~0.41 구간에서만 변하고 나머지는 평평합니다. 그림의 임계값(0.35±0.05, 0.40±0.01)과 그림자 색(0.38, 0.589)은 이 프로젝트 셰이더의 기본값입니다.

## 셰이더 안에서 계산하면 그림자를 받지 못합니다

처음 만든 셰이더는 라이트 방향 노드로 N·L을 직접 계산하고, 결과를 이미시브(Emissive)로 출력했습니다. Base Color는 비워 두었습니다. 이렇게 하면 엔진의 조명 계산을 완전히 건너뜁니다.

```text
// ❌ 엔진 조명을 거치지 않는 구조
L        = dot(PixelNormal, SkyAtmosphereLightDirection) * 0.5 + 0.5
Emissive = baseColor * toon(L)
BaseColor = 0
```

엔진의 그림자 맵은 조명 계산 단계에서 적용됩니다. 조명을 건너뛰면 그림자 맵도 들어오지 않습니다. N·L은 표면 방향만 보기 때문에, 다른 물체가 빛을 가려도 알 수 없습니다. 이미시브는 노출(Exposure)의 영향을 받아 장면마다 밝기가 달라지는 문제도 있었습니다.

해결은 순서를 바꾸는 것입니다. 캐릭터는 평범한 Default Lit 머티리얼로 그려 엔진이 그림자까지 계산하게 하고, 그 결과를 후처리(Post Process)에서 계단으로 자릅니다.

![셰이더 안에서 계산하는 구조와 엔진 조명 뒤 후처리하는 구조 비교](/images/toon-shading-1/03_pipeline.png)

핵심은 주황색 칸입니다. 화면의 최종 색을 물체 고유색(Diffuse)으로 나누면 텍스처 색이 빠지고 빛의 양만 남습니다. 그 빛의 양에는 그림자 맵이 이미 들어 있습니다.

```text
// ✅ 후처리에서 빛의 양을 뽑아 계단으로 자르기
light = SceneColor / max(DiffuseColor, 0.001)      // 텍스처 색 제거
L     = saturate(dot(light, (0.3, 0.59, 0.11)) / LightScale)
tone  = toon(L)                                    // 위와 같은 SmoothStep 2단계
out   = lerp(SceneColor, DiffuseColor * tone, characterMask)
```

캐릭터에만 적용해야 하므로 커스텀 스텐실(Custom Stencil)로 마스크를 만듭니다. 캐릭터 메시에 스텐실 값 1을 쓰고, 후처리에서 그 값인 픽셀만 바꿉니다.

이 방식에도 한계가 있습니다. 후처리는 화면 전체에 한 번 적용되므로 재질마다 다른 그림자 색을 주기 어렵습니다. 얼굴과 눈처럼 조명을 받으면 오히려 지저분해지는 부위도 있습니다. 이 둘은 아래에서 따로 처리합니다.

## 림라이트는 테두리만 밝혀 실루엣을 띄웁니다

툰 셰이딩은 면을 단색으로 칠하기 때문에, 어두운 배경 앞에서 캐릭터 윤곽이 묻히기 쉽습니다. 림라이트(Rim Light)는 시선과 거의 수직인 테두리만 밝혀 실루엣을 띄웁니다.

가장 흔한 방법은 프레넬(Fresnel)입니다. 노멀과 시선 방향의 내적이 0에 가까울수록, 즉 가장자리일수록 값이 커집니다.

```text
fresnel = base + (1 - base) * pow(1 - dot(N, V), exponent)   // base 0.02, exponent 2
rim     = smoothstep(0.70 - 0.45, 0.70 + 0.45, fresnel)
color   = lerp(color, color * rimColor, rim)
```

![림라이트 유무 비교와 각도별 Fresnel 값](/images/toon-shading-1/04_rim.png)

오른쪽 그래프에서 SmoothStep을 거친 값은 시선과 60° 이상 기울어진 곳에서만 커집니다. 그래서 테두리에 얇은 띠만 생깁니다.

후처리에서는 메시의 노멀을 직접 읽을 수 없으므로 GBuffer의 WorldNormal을 씁니다. 프레넬 림은 곡면이 완만하면 두껍고 평평하면 사라지는 한계가 있습니다. 두께를 일정하게 하려면 깊이 버퍼를 노멀 방향으로 밀어 비교하는 화면 공간 깊이 림을 씁니다. 이 프로젝트에서는 아직 프레넬 방식입니다.

## 얼굴은 미리 그린 그림자 경계를 잘라 씁니다

얼굴에 N·L을 그대로 쓰면 코와 볼의 굴곡을 따라 얼룩 같은 그림자가 생깁니다. 애니메이션에서는 얼굴 그림자를 깔끔한 선 하나로 그립니다.

이를 위해 SDF(Signed Distance Field) 텍스처를 씁니다. 얼굴 UV 위에 "빛이 몇 도에서 올 때 여기까지 그림자가 진다"를 회색값으로 그려 둔 텍스처입니다. 실행 중에는 빛 각도로 임계값만 바꿔 이 텍스처를 자릅니다.

```text
Fwd, Right = 머리의 앞/오른쪽 방향 (수평면에 투영, 정규화)
Lxy        = 빛 방향 (수평면에 투영, 정규화)
FdotL      = dot(Fwd, Lxy)
RdotL      = dot(Right, Lxy)
uv         = RdotL > 0 ? (1 - u, v) : (u, v)          // 빛이 오는 쪽에 맞춰 좌우 반전
threshold  = 0.5 - 0.5 * FdotL                        // 정면 빛 0, 옆 빛 0.5
lit        = smoothstep(threshold - 0.01, threshold + 0.01, SDF(uv))
color      = lerp(base * faceShadowColor, base, lit)
```

![가상 SDF 텍스처와 빛 각도별 얼굴 그림자](/images/toon-shading-1/05_sdf.png)

그림의 SDF는 설명을 위해 만든 가상 텍스처입니다. 빛이 정면에서 옆으로 돌수록 임계값이 커지고, 그림자 경계가 한쪽 볼에서 코 쪽으로 이동합니다.

얼굴 머티리얼은 Unlit으로 두고 결과를 이미시브로 출력합니다. 그러면 GBuffer의 Diffuse가 0이 되어 앞의 후처리 마스크에서 자동으로 빠집니다. 그림자 색은 회색 대신 혈색이 도는 분홍(0.95, 0.74, 0.69)을 씁니다.

## 눈은 조명에서 빼고 깊이감과 광택을 더합니다

눈에 조명을 그대로 적용하면 위 눈꺼풀 그림자가 눈동자를 덮어 탁해집니다. 처음 만든 셰이더에서 눈이 생기 없어 보인 원인이 이것이었습니다. 그래서 눈도 Unlit으로 그리고 세 가지를 더합니다.

1. <strong>시차(Parallax)</strong>: `BumpOffset`으로 가운데가 깊은 높이를 주어, 보는 각도에 따라 홍채가 안쪽에 있는 것처럼 밀립니다.
2. <strong>광택막</strong>: 홍채 위쪽을 넓게 덮는 초승달 모양 텍스처를 약하게(0.15) 더해 유리 같은 광택을 냅니다.
3. <strong>밝기 보정 최소화</strong>: 눈 텍스처에는 반짝이는 점과 위쪽 그림자가 이미 그려져 있습니다. 밝기를 2배로 올려 두었더니 아래쪽 홍채가 하얗게 날아가 반짝임이 묻혔습니다. 그래서 밝기를 1배로 되돌렸습니다.

광택 텍스처는 처음에 작은 반짝이 점으로 잘못 해석해 밝게 키웠고, 눈 전체에 흰 얼룩이 생겼습니다. 텍스처를 열어 보니 넓은 면이었고, 원래 용도대로 약하게 더하는 것으로 바꿨습니다. 멀리서 눈이 뿌옇게 번지던 문제는 이 텍스처의 밉맵(Mipmap)이 번지는 것으로 보고 밉맵을 껐습니다.

## 외곽선은 메시를 한 번 더 부풀려 그립니다

툰 셰이딩의 검은 외곽선은 인버티드 헐(Inverted Hull)로 만듭니다. 같은 메시를 하나 더 겹쳐 두고, 정점을 노멀 방향으로 조금 밀어낸 뒤 뒷면만 그립니다.

```text
// 외곽선 메시의 World Position Offset
offset   = VertexNormalWS * outlineThickness   // 0.1
// 앞면은 버리고 뒷면만 단색으로 출력
```

![노멀 방향으로 부풀린 메시의 뒷면이 외곽선이 되는 원리](/images/toon-shading-1/06_hull.png)

카메라 쪽 앞면은 원래 메시에 가려지거나 버려지고, 바깥으로 삐져나온 뒷면만 테두리처럼 남습니다. 메시를 두 번 그리므로 비용이 들고, 두께가 거리와 상관없이 고정이라 멀어지면 1픽셀보다 얇아져 반짝일 수 있습니다. 외곽선 메시는 본체와 같은 포즈를 따라가도록 리더 포즈(Leader Pose)를 지정해야 애니메이션 중에 어긋나지 않습니다.

<details>
<summary>1. 셰이더 안에서 N·L로 명암을 계산하면 왜 다른 물체의 그림자가 지지 않나요</summary>

N·L은 표면 방향과 빛 방향만 보기 때문에 빛이 가려졌는지 알 수 없습니다. 그림자 맵은 엔진의 조명 단계에서 적용되는데, 결과를 이미시브로 내보내면 이 단계를 건너뜁니다. 그래서 캐릭터는 Default Lit으로 그리고, 화면 색을 Diffuse로 나눠 그림자가 포함된 빛의 양을 얻은 뒤 후처리에서 단계 처리합니다.

</details>

<details>
<summary>2. 얼굴에 N·L 대신 SDF를 쓰는 이유는 무엇인가요</summary>

얼굴은 코와 볼의 굴곡이 커서 N·L을 쓰면 그림자가 얼룩처럼 생깁니다. SDF는 빛 각도별 그림자 경계를 미리 그려 둔 텍스처라, 임계값(0.5 - 0.5×FdotL)만 바꾸면 깔끔한 선 하나로 그림자가 움직입니다.

</details>

<details>
<summary>3. SmoothStep의 두 경계를 좁게 잡을수록 어떻게 되나요</summary>

경계 사이에서만 값이 변하므로 좁을수록 계단에 가까워집니다. 이 프로젝트는 그림자 경계를 0.35±0.05, 중간톤 경계를 0.40±0.01로 잡아 중간톤이 아주 좁은 띠로 나타납니다. 너무 좁으면 화면 해상도가 낮을 때 경계가 계단처럼 깨져 보일 수 있습니다.

</details>
