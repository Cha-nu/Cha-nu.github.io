## 들어가며

3편과 4편에는 0.62, 3.19, 125.36 같은 숫자가 많이 나옵니다. 대부분 AI 어시스턴트(Claude)가 텍스처와 모델 파일을 읽어 뽑아 준 값입니다. 글을 올리고 나서, AI가 없었다면 이 값들을 어떻게 구했어야 하는지가 궁금해졌습니다.

이 글은 그 질문을 AI에게 다시 묻고 정리한 것입니다. 기법마다 어떤 식인지, 숫자를 직접 구하려면 무엇을 보면 되는지, HLSL로는 어떻게 쓰는지를 적었습니다. 노드 그래프 화면은 3편에 있습니다.

<strong>AI 활용</strong>: 본문의 설명, HLSL, 그림은 AI가 썼습니다. 수치는 3편과 4편에서 프로젝트에 실제로 넣은 값입니다.

## 직접 맞출 때 쓰는 세 가지 방법

AI가 한 일은 대부분 아래 세 가지로 바꿔 할 수 있습니다.

| AI가 한 일 | 직접 하는 방법 |
| --- | --- |
| 텍스처 채널이 무엇인지 해석 | 텍스처 뷰어에서 R, G, B를 하나씩 켜 봅니다 |
| 띠 위치, 마스크 경계값 찾기 | 그 채널을 Base Color에 그대로 연결해 화면에서 봅니다 |
| 눈 위치, 본 사이 거리 읽기 | 블렌더나 스켈레탈 메시 에디터에서 좌표를 읽습니다 |

- <strong>채널 보기</strong>: 한 채널이 부드러운 그라데이션이면 좌표이고, 얼룩이나 줄무늬면 마스크입니다. 머리카락의 `_HN` 텍스처는 G 채널이 뿌리에서 끝으로 가는 그라데이션이었습니다.
- <strong>값을 색으로 찍기</strong>: 머티리얼에서 확인하고 싶은 값을 Base Color나 Emissive에 바로 연결하면 그 값이 밝기로 보입니다. 숫자를 미리 계산하지 않아도, 인스턴스에서 파라미터를 움직이며 화면으로 맞출 수 있습니다.
- <strong>좌표 읽기</strong>: 위치로 자르는 마스크는 메시에서 해당 부위의 정점을 골라 좌표 범위를 읽으면 됩니다.

4편에서 물리를 여러 번 잘못 맞춘 것은 화면을 보지 않고 값을 추측했기 때문이었습니다. 눈으로 보면서 맞추는 쪽이 느려 보여도 더 정확합니다.

## 한 지점 근처만 남기기: 하이라이트 띠

머리카락 띠는 "좌표가 어떤 값 근처인 곳만 밝게"입니다. 기준값과의 거리를 폭으로 나눠 1에서 빼면, 기준값에서 1이고 폭만큼 떨어지면 0이 되는 삼각형이 됩니다.

![가닥 방향 좌표에 따른 띠 세기. 0.62에서 1이고 양쪽으로 0.18만큼 벗어나면 0이 되는 삼각형 모양입니다.](/images/toon-shading-5/01_band.png)

가로축이 머리카락 뿌리에서 끝으로 가는 좌표입니다. `Position`을 키우면 삼각형이 오른쪽, 즉 머리끝 쪽으로 옮겨 갑니다.

```hlsl
// hn: _HN 텍스처(좌표), hm: _HM 텍스처(줄무늬 마스크)
float  band = saturate(1.0 - abs(hn.g - HLPosition) / HLWidth);
float3 hl   = (hm.r * HLColor * band + saturate(hm.g - 0.4) * HL2Intensity) * HLIntensity;
```

<strong>직접 맞추려면</strong>: `hn.g`를 Base Color에 연결해 머리카락이 검정에서 흰색으로 변하는 것을 확인합니다. 그다음 `band`만 연결해 두고 `HLPosition`을 움직여 띠가 원하는 높이에 오는 값을 찾습니다. 앞머리는 0.55가 화관 바로 아래, 0.7이 눈썹 높이였고 0.62로 정했습니다.

## 위치로 자르기: 눈 타원 마스크

눈을 덧그릴 때 흰자가 눈 주변 피부까지 번지지 않도록, 눈꺼풀이 열린 자리만 남기는 마스크입니다. 원은 "중심에서의 거리가 반지름보다 작다"로 쓸 수 있습니다. 타원은 가로와 세로를 각자의 반지름으로 나눠 원으로 만든 뒤 같은 식을 씁니다.

![로컬 좌표 평면에 그린 두 개의 타원 마스크. 중심은 X 3.19, Z 125.36이고 반지름은 가로 1.65, 세로 0.82입니다.](/images/toon-shading-5/02_ellipse.png)

X에 절댓값을 씌우면 왼쪽 눈과 오른쪽 눈이 같은 식 하나로 처리됩니다. 가장자리는 `SmoothStep(0.9, 1.05)`로 부드럽게 끊습니다.

```hlsl
// p: 스키닝 전 로컬 위치. 포즈가 바뀌어도 값이 변하지 않습니다.
float2 e   = float2((abs(p.x) - 3.19) / 1.65, (p.z - 125.36) / 0.82);
float  eye = 1.0 - smoothstep(0.9, 1.05, length(e));
```

스키닝 전 위치를 쓰는 이유는 캐릭터가 움직여도 "얼굴 위의 같은 자리"를 가리켜야 하기 때문입니다. 월드 위치를 쓰면 캐릭터가 걸어가는 순간 마스크가 얼굴에서 벗어납니다.

<strong>직접 맞추려면</strong>: 블렌더에서 눈꺼풀이 열린 테두리의 정점을 선택해 X와 Z의 최솟값, 최댓값을 읽습니다. 두 값의 평균이 중심이고 차이의 절반이 반지름입니다. 이 모델에서 눈이 열린 부분의 절반 크기는 가로 1.56, 세로 0.76이었고, 반지름은 그보다 조금 크게 잡았습니다.

## 가려진 곳만 고르기: 깊이 차이

앞머리에 가려진 눈썹만 비치게 하려면, 지금 그리는 픽셀 앞에 무언가 있는지 알아야 합니다. 화면에 이미 그려진 깊이(Scene Depth)와 내 픽셀의 깊이(Pixel Depth)를 빼면 그 차이가 나옵니다.

![깊이 차이 D에 따른 Cover Mask 값. 0.3에서 1로 올라가고 4에서 8 사이에 0으로 내려갑니다.](/images/toon-shading-5/03_cover.png)

차이가 0.3보다 작으면 가려지지 않은 것으로 봅니다. 4를 넘으면 서서히 줄여 8에서 0으로 만듭니다. 상한이 없으면 캐릭터 앞에 멀리 선 물체 위로도 눈썹이 비칩니다.

```hlsl
float d     = PixelDepth - SceneDepth;                    // 양수면 내 앞에 무언가 있음
float cover = step(0.3, d) * (1.0 - smoothstep(4.0, 8.0, d));
cover      *= step(0.01, dot(SceneBaseColor, float3(1, 1, 1)));   // 아무것도 안 그려진 곳 제외
```

<strong>직접 맞추려면</strong>: 하한 0.3은 얼굴 자신과의 오차를 넘기는 값으로, 0에서 조금씩 올리며 얼굴 전체가 비치지 않게 되는 지점을 찾습니다. 상한은 메시에서 앞머리와 이마 사이 거리를 재서 그보다 넉넉하게 잡습니다.

UV 범위로 자르는 Area Mask는 더 단순합니다. `step(a, x)`는 x가 a 이상이면 1이므로, 네 변의 조건을 곱하면 사각형이 됩니다.

```hlsl
float area = step(0.2, uv.x) * step(uv.x, 0.8) * step(0.67, uv.y);
```

언리얼의 `Step` 노드는 위쪽 핀이 Y, 아래쪽이 X이고 결과는 `X >= Y`입니다. 작업 중에 이 핀을 반대로 꽂아 범위가 뒤집힌 적이 있습니다.

## 가장자리만 밝히기: 프레넬

표면의 노멀과 카메라 방향을 내적하면, 카메라를 정면으로 보는 면은 1이고 옆을 보는 면은 0입니다. 이 값을 뒤집으면 가장자리만 밝아집니다. 1편의 림라이트와 같은 원리입니다.

```hlsl
float  f       = 1.0 - saturate(dot(N, V));              // 정면 0, 가장자리 1
float3 fresnel = smoothstep(RangeMin, RangeMax, f) * FresnelColor * Intensity;
```

`SmoothStep`의 범위로 광택이 시작하는 각도와 끝나는 각도를 정합니다. 범위를 좁히면 가장자리에 얇은 선처럼 붙고, 넓히면 면 안쪽까지 퍼집니다.

금속에만 얹은 MatCap은 노멀을 카메라 기준으로 바꿔 구 모양 그림을 찍는 좌표로 씁니다.

```hlsl
float2 mcUV   = mul(N, (float3x3)View).xy * 0.5 + 0.5;    // -1~1을 0~1로
float3 matcap = Sample(MatCapTex, mcUV).rgb
              * smoothstep(0.7, 0.9, typeMask.g) * MatCapIntensity;
```

<strong>직접 맞추려면</strong>: `typeMask.g`를 Base Color에 연결하면 부위마다 다른 회색으로 칠해집니다. 금속 부분의 밝기가 다른 부위보다 뚜렷이 높은지 보고, 그 사이를 `SmoothStep`의 범위로 잡습니다. 이 모델에서 금속은 대략 0.75보다 큰 값이었습니다.

## 밝은 색은 두고 중간만 내리기: Power

리본은 거의 흰색 위에 옅은 회색으로 주름이 그려져 있어 흰 덩어리로 보였습니다. 거듭제곱은 1을 그대로 두고 그보다 작은 값만 더 낮춥니다.

![Power 1과 Power 2의 곡선. 0.9는 0.81로, 0.5는 0.25로 내려가고 1은 그대로입니다.](/images/toon-shading-5/04_power.png)

0.9와 1의 차이는 0.1인데, 제곱하면 0.81과 1로 0.19가 됩니다. 밝은 영역 안에서의 차이가 두 배 가까이 벌어져 주름이 드러납니다.

```hlsl
float3 base = pow(tex.rgb, BaseColorPower) * BaseColorBrightness;
```

밝기를 곱하는 것과는 결과가 다릅니다. 0.7을 곱하면 1도 0.7이 되어 흰색이 사라집니다. 3편에서 캐릭터 전체에 0.7을 곱했다가 꽃이 회색이 된 것이 이 경우입니다.

캐릭터 픽셀에만 밝기를 적용할 때는 마스크로 1과 밝기 값 사이를 고릅니다.

```hlsl
float  m     = saturate(1.0 - abs(Stencil - StencilValue));   // 캐릭터 1, 배경 0
float3 scene = SceneColor * lerp(1.0, BaseColorBrightness, m);
```

## 일부 픽셀만 그리기: 디더링 반투명

베일은 Translucent가 아니라 Masked로 두고, 픽셀마다 그릴지 말지를 정해 반투명처럼 보이게 했습니다. 픽셀마다 다른 문턱값을 주고 불투명도와 비교합니다.

```hlsl
float opacity = lerp(VeilOpacity, 1.0, fresnel);           // 가장자리는 더 불투명하게
clip(opacity - DitherPattern(ScreenPosition));             // 문턱값보다 작으면 그리지 않음
```

불투명도가 0.85면 픽셀 100개 중 약 85개가 그려집니다. 그대로 보면 점무늬지만, 시간축 안티에일리어싱이 프레임 사이를 섞어 매끈하게 만듭니다. `DitherPattern`은 엔진의 `DitherTemporalAA` 노드가 하는 일을 풀어 쓴 이름입니다.

이 방식을 쓴 이유는 2편의 후처리가 GBuffer를 읽기 때문입니다. Translucent는 GBuffer에 쓰이지 않아 툰 처리에서 빠집니다.

## 닿지 않는 크기 구하기: 충돌 구

4편의 물리는 본마다 반지름이 있고, 몸통 본에 붙인 구가 그것을 밀어냅니다. 서 있을 때 닿지 않으려면 두 반지름의 합이 둘 사이 거리보다 작아야 합니다.

![왼쪽은 골반 구 9.5와 치마 본 3이 겹친 그림, 오른쪽은 구 8.3과 본 2가 떨어진 그림. 두 경우 모두 중심 사이 거리는 10.7입니다.](/images/toon-shading-5/05_clearance.png)

치마가 위로 떴을 때가 왼쪽입니다. 뚫림을 막으려고 구를 9.5, 본 반지름을 3으로 키웠는데, 합 12.5가 거리 10.7을 넘어서 가만히 서 있어도 치마가 밀려났습니다.

```text
구 반지름 + 본 반지름 <= 기준 자세에서 구 중심과 본 사이 거리
```

<strong>직접 맞추려면</strong>: 스켈레톤에서 두 본의 위치를 읽어 거리를 구하고, 위 식을 만족하는 가장 큰 값에서 시작합니다. 다만 이 식은 서 있을 때의 조건일 뿐입니다. 달릴 때 뚫리지 않으려면 구가 커야 하고, 서 있을 때 뜨지 않으려면 작아야 해서, 결국 움직이는 화면을 보며 부위마다 절충해야 합니다.

<details><summary>앞머리 띠를 더 아래로 내리려면 어느 값을 어느 방향으로 바꿔야 하나요?</summary>

`HLPosition`을 키웁니다. 좌표가 뿌리에서 끝으로 갈수록 커지므로, 0.62에서 0.7로 올리면 띠가 이마 중간에서 눈썹 높이로 내려갑니다.

</details>

<details><summary>눈 타원 마스크에 월드 위치 대신 스키닝 전 로컬 위치를 쓰는 이유는 무엇인가요?</summary>

마스크의 중심 (3.19, 125.36)은 메시 기준 자세에서의 눈 위치입니다. 월드 위치는 캐릭터가 이동하거나 고개를 돌리면 달라지므로 마스크가 눈에서 벗어납니다. 스키닝 전 로컬 위치는 포즈와 무관하게 정점마다 고정된 값입니다.

</details>

<details><summary>리본 디테일을 살릴 때 밝기를 곱하지 않고 Power를 쓴 이유는 무엇인가요?</summary>

곱하기는 모든 값을 같은 비율로 내려서 1도 0.7이 됩니다. Power 2는 1을 그대로 두고 0.9를 0.81로 내리므로, 흰색은 유지하면서 0.9와 1의 차이를 0.1에서 0.19로 벌립니다.

</details>

## 마치며

식 자체는 대부분 한두 줄이었습니다. 거리를 폭으로 나누기, 중심을 빼고 반지름으로 나누기, 두 깊이를 빼기, 제곱하기 정도입니다. 어려운 쪽은 식이 아니라 그 식에 넣을 숫자를 찾는 일이었습니다.

AI는 파일을 직접 읽어 그 숫자를 빠르게 뽑아 주었습니다. 다만 같은 숫자는 채널을 켜 보고, 값을 화면에 찍어 보고, 메시에서 좌표를 읽으면 직접 구할 수 있습니다. 화면을 보며 맞춰야 하는 물리에서는 오히려 그쪽이 맞는 방법이었습니다.

이 글을 쓴 뒤 흰 조명에서 찍은 원작 화면을 구해 색을 다시 맞췄습니다. 그 과정과 후처리 방식에 대한 회고는 [6편](/posts/toon-shading-6/)에 적었습니다.
