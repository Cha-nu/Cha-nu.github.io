## 들어가며

ProjectB는 모스 부호로 지원요청을 부르는 쿼터뷰 슈터입니다. 주무기는 사거리 안에서 가장 가까운 적을 자동으로 조준해 쏩니다.

이번 기록은 두 가지입니다. 자동 조준이 적을 찾는 방식을 격자 탐색과 시야 검사로 바꾼 일, 그리고 모스 부호 입력이 조금 어긋나도 받아 주는 장치들입니다.

---

## 요구사항

- 자동 조준이 적 전체를 하나씩 훑는 대신, 이미 있는 격자에서 사거리 안의 칸만 훑게 합니다.
- 건물이나 컨테이너에 가린 적은 건너뜁니다. 벽에 대고 총을 쏘지 않게 하기 위해서입니다.
- 결과가 기존 방식과 같아야 합니다. 가장 가까운 적이 바뀌면 안 됩니다.
- 증원이 몰려 적이 최대치(300명)에 가까울 때, 그리고 적이 한곳에 몰려 있을 때 어떻게 동작하는지 확인합니다.

---

## 한 일

1. `nearest()`를 격자 고리 탐색으로 바꿨습니다. 내 칸부터 바깥쪽으로 한 겹씩 넓히고, 더 바깥 칸이 지금까지 찾은 적보다 가까울 수 없으면 멈춥니다.
2. 시야 검사 옵션을 넣었습니다. 높이 16 이상인 엄폐물(건물, 컨테이너)이 선분을 막으면 그 적은 건너뜁니다. 플레이어 주무기, 센트리 건, 호위 드론에 켰고, 하늘에서 쏘는 건십과 유도 미사일에는 껐습니다.
3. 플레이어 쪽 시야 결과를 적마다 0.1\~0.2초 기억하는 캐시를 넣었습니다. 벽 뒤에 적이 몰린 경우 때문입니다(아래 결과 절).
4. 탐색 과정을 바닥에 그리는 디버그 표시를 만들었습니다. 이 글의 스크린샷이 그 화면입니다.

---

## 아이디어와 설계

맵은 3000 x 3000 단위이고, 이미 50 x 50 단위 칸(60 x 60개)의 격자가 있었습니다. 매 프레임 적을 칸에 다시 넣고, 그동안은 총알 충돌과 지뢰 판정에만 썼습니다. 새 자료 구조를 만들기보다 이 격자를 그대로 쓰기로 했습니다.

| 방법 | 장점 | 단점 | 선택 |
| --- | --- | --- | --- |
| 전수 탐색 | 단순하고 항상 맞음 | 적 수에 비례해 느려짐 | |
| 격자에서 사거리 사각형 전체 | 구현이 쉬움 | 사거리 600이면 625칸을 매번 봄 | |
| 격자 고리 탐색 + 조기 종료 | 가까운 적이 있으면 몇 칸만 봄 | 적이 한 칸에 몰리면 이득이 줄어듦 | ✅ |
| 쿼드트리 | 밀도 차이에 강함 | 매 프레임 다시 짓는 비용, 코드 추가 | |

고리 탐색에서 멈추는 조건은 "이번 고리에 있는 적까지의 최소 거리"가 지금까지 찾은 거리보다 큰지입니다. 내 위치가 칸 안 어디든 될 수 있으므로 고리 r의 최소 거리는 (r - 1) x 50으로 잡고, 적 반지름 최대값 30을 뺐습니다.

```gdscript
for ring in maxr + 1:
	if (ring - 1) * TS - MAX_ER > bd:   # 남은 고리는 지금 찾은 적보다 멀다
		break
	for 고리 위의 칸:
		for e in grid[칸]:
			var d = 거리(e) - e.r
			if d < bd:
				if not need_los or _sees(x, y, e, cache):   # 더 가까울 때만 시야 검사
					bd = d
					b = e
```

시야 검사는 비싼 편이라 "지금 찾은 적보다 가까운 후보"일 때만 합니다. 트인 곳에서는 첫 후보가 바로 통과하고 거리 기준이 줄어들기 때문에 검사가 몇 번에 끝납니다.

## 결과

측정 조건은 Windows 11 데스크톱, Godot 4.7.2, GDScript입니다. 시간은 1회 탐색 평균이고, 같은 측정을 3번 돌렸습니다. 측정 코드와 원본 기록은 `research/project-b-nearest/`에 있습니다. 모바일 기기에서는 아직 재지 않았습니다.

먼저 정확도입니다. 무작위 400지점에서 사거리 230/290/600으로 기존 전수 탐색과 비교했고, 3번 모두 결과가 다른 경우는 0건이었습니다.

![벽 뒤 적을 건너뛰는 장면. 플레이어 오른쪽 건물 뒤의 가까운 적으로는 빨간 선이, 아래쪽 트인 곳의 먼 적으로는 초록 선이 그어져 있습니다. 바닥의 파란 칸은 이번에 훑은 격자 칸입니다.](/images/devlog/project-b/2026-11-10/01_trace_wall.png)

*빨간 선은 더 가깝지만 건물에 가려 건너뛴 적, 초록 선은 실제로 고른 적입니다. 시야 검사를 끄면 건물 뒤의 적을 고릅니다.*

| 상황 (적 수) | 격자 | 격자 + 시야 | 전수 탐색 |
| --- | --- | --- | --- |
| 맵 전체에 흩어짐 (300명) | 8µs | | 62\~64µs |
| 플레이어 앞에 몰림 (150명) | 12.0\~14.6µs | 15.1\~17.6µs | 30.7\~31.3µs |
| 벽 바로 뒤에 몰림 (150명) | 42.7\~43.1µs | 492.5\~495.6µs | 30.8µs |

적이 흩어져 있을 때 가장 크게 빨라졌습니다. 300명에서 62µs가 8µs로 줄었습니다.

## 적이 몰린 곳에서는 어떻게 탐색하나

이 질문 때문에 밀집 상황을 따로 만들어 쟀습니다. 결론은 "가장 가까운 적이 몰린 무리 안에 있으면 빠르고, 몰린 무리가 전부 가려져 있으면 느리다"입니다.

![밀집 상황. 플레이어 왼쪽에 적 150명이 모여 있고, 바닥의 파란 칸은 플레이어 주변 7 x 7칸만 칠해져 있습니다. 초록 선이 무리의 가장 앞쪽 적을 가리킵니다.](/images/devlog/project-b/2026-11-10/02_trace_crowd.png)

*반경 90 안에 150명이 몰려 있어도 2고리(25칸)만 훑고 멈춥니다. 시야 검사는 1번입니다. 무리 중 그 25칸에 들어온 적만 거리를 계산하므로 전수 탐색의 절반 이하 시간입니다.*

문제는 무리가 벽 바로 뒤에 있을 때입니다. 150명 모두 사거리 안에서 지금까지 찾은 적보다 가까우니 전부 시야 검사를 받고, 전부 실패합니다. 가장 가까운 적을 못 찾았으니 거리 기준이 줄지 않아 사거리 끝(7고리, 225칸)까지 다 훑습니다.

![최악의 경우. 플레이어 오른쪽 건물 바로 뒤에 적 150명이 있고, 바닥은 사거리 전체 225칸이 파랗게 칠해져 있습니다. 초록 선은 없고 건물 쪽으로 빨간 선만 있습니다.](/images/devlog/project-b/2026-11-10/03_trace_worst.png)

*탐색 1번에 시야 검사 150번, 495µs가 걸렸습니다. 30fps 한 프레임(33ms)의 1.5% 정도지만, 플레이어 한 명의 조준 하나에 쓰기에는 큰 값입니다.*

## 막힌 점과 해결

- 문제: 벽 뒤에 적이 몰리면 매 프레임 150번씩 시야 검사를 합니다.
  - 원인: 시야 검사가 실패하면 거리 기준이 줄지 않아, 조기 종료도 일어나지 않고 모든 후보가 검사를 받습니다.
  - 해결: 플레이어 쪽 탐색에 한해 적마다 시야 결과를 0.1\~0.2초 기억합니다. 만료 시각을 무작위로 흩어 놓아 검사가 여러 프레임에 나뉩니다. 프레임당 시야 검사가 150번에서 30.2\~30.4번으로, 시간이 492.5\~495.6µs에서 189.9\~193.4µs로 줄었습니다.
  - 남은 것: 시야 검사를 빼도 이 상황의 격자 탐색(43µs)은 전수 탐색(31µs)보다 느립니다. 무리 전체가 훑는 칸 안에 있으면 칸을 도는 비용만 더해지기 때문입니다.

캐시는 플레이어 위치가 0.2초 사이에 크게 바뀌지 않는다는 가정에 기대고 있습니다. 그래서 위치가 매번 다른 센트리 건과 호위 드론에는 넣지 않았습니다.

## 모스 부호 입력의 관용 장치

ProjectB는 버튼 하나를 짧게(점), 길게(선) 눌러 지원요청 부호를 입력합니다. 손으로 리듬을 맞추는 입력이라 엄격하게 받으면 실수가 많습니다. 그래서 코요테 타임(Coyote Time)처럼 조금 늦거나 어긋난 입력을 받아 주는 장치를 몇 가지 두었습니다.

![모스 부호 입력 중인 HUD. 왼쪽 아래 전건 버튼 둘레에 누른 시간을 보여 주는 금색 고리가 있고, 그 오른쪽에 지금까지 입력한 점과 선이 표시되어 있습니다. 지원요청 카드의 부호 중 입력한 부분이 노랗게 칠해져 있습니다.](/images/devlog/project-b/2026-11-10/04_morse_input.png)

*전건을 누르고 있는 동안 버튼 둘레 고리가 차오릅니다. 고리가 다 차면 손을 떼기 전에 선으로 확정됩니다.*

| 장치 | 동작 | 값 |
| --- | --- | --- |
| 점/선 기준 당기기 | 다음에 올 수 있는 기호가 선뿐이면 기준을 짧게, 점뿐이면 길게 잡습니다 | 0.095초 / 0.15초 / 0.215초 |
| 누르는 중 확정 | 기준 시간을 넘기면 손을 떼지 않아도 그 순간 선으로 확정합니다 | 기준 시간 |
| 오타 한 번 허용 | 어느 부호에도 맞지 않는 기호가 처음 들어오면 버리고 입력을 이어 갑니다 | 1회 |
| 겹치는 부호 대기 | 짧은 부호가 긴 부호의 앞부분이면 바로 쓰지 않고 다음 입력을 기다립니다 | 0.6초 |
| 재충전 직전 예약 | 재사용 대기가 조금 남았을 때 입력하면 "대기 중"으로 받아 두었다가 준비되는 순간 발동합니다 | 남은 시간 1.2초 이하 |
| 입력 유지 | 마지막 입력 뒤 이 시간 동안 아무것도 안 하면 입력을 비웁니다 | 2.2초 |

코요테 타임과 가장 비슷한 것은 재충전 직전 예약입니다. 0.5초쯤 일찍 입력해도 실패로 처리하지 않고, 준비되자마자 발동합니다. 입력을 버리지 않고 받아 둔다는 점에서는 입력 버퍼에 더 가깝습니다.
